# Windows Keyboard for Mac v0.4.1

This unsigned preview adds optional VS Code integrated-terminal keybindings
and clarifies which file to import into Karabiner-Elements.

## VS Code integrated terminal

The ZIP now includes `extras/vscode-terminal-keybindings.json`. Append its
entries to VS Code's user keybindings to make translated physical Ctrl+C send
Interrupt, Ctrl+Shift+C/V copy/paste, and Ctrl+V send the shell's raw control
sequence while the integrated terminal has focus. Editor bindings keep their
existing behavior.

This is an optional VS Code setting used alongside either Karabiner edition.
It is not installed automatically or imported into Karabiner. The bindings
also affect Apple-keyboard Command shortcuts in that terminal because VS Code
cannot identify the originating keyboard. The troubleshooting guide explains
installation, verification, and removal.

## Community imports

The README and quick start now link to the importable community rule. The
device-scoped `dist/windows-keyboard-for-mac-profile.json` remains an installer
template and cannot be imported directly through Complex Modifications.

## Spotlight investigation

The Tahoe Spotlight report in issue #7 remains under investigation. This

## Requirements and assets

- macOS 15 or newer and Karabiner-Elements 16 or newer
- `Windows-Keyboard-for-Mac-v0.4.1.zip`
- `Windows-Keyboard-for-Mac-v0.4.1.zip.sha256`

The device-scoped profile and installer behavior are unchanged. The package is
not Apple-signed or notarized; Karabiner must be installed separately.

## Verification

The optional bindings were exercised in VS Code 1.137.0 on macOS 26.2 with
software-generated Command events. Before installation, Command+C did not
reach a terminal byte probe; raw Control+C worked as a positive control. After
installation, Command+C delivered ETX and interrupted a separate waiting
process with SIGINT. Shift+Command+C/V copied and pasted known test text,
Command+V delivered `0x16`, and ordinary editor copy/paste continued working.

These checks validate VS Code's binding layer. They do not simulate a physical
keyboard passing through Karabiner's device matching. Physical keyboard
confirmation remains a separate check, and issue #7 is not resolved by these
tests.
