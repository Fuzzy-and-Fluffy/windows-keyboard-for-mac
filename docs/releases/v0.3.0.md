# Windows Keyboard for Mac v0.3.0

This release makes window closing and the function-key row behave more like
Windows while preserving device isolation and reversible installation.

## Highlights

- `Alt+F4` now closes the active top-level window instead of quitting every
  window owned by the macOS app.
- Chrome, Edge, Safari, Firefox, Brave, and Opera close the current browser
  window, including its tabs.
- Finder closes its front window regardless of whether that window contains
  one tab or several.
- Other supported macOS apps receive `Command+W`; remote desktops and virtual
  machines continue to receive their native physical modifiers.
- `Ctrl+F4` remains the separate close-document or close-tab shortcut.
- F1 through F12 remain standard function keys on enrolled Windows keyboards
  even when macOS media-key mode is enabled. Finder `F2`, browser `F5`, and
  modified F-key shortcuts still take priority.
- The public profile does not reserve `Ctrl+Space` for a dictation or other
  personal app shortcut.

## Safety and privacy

- Only keyboards explicitly selected during installation are enrolled.
- The MacBook built-in keyboard, Apple keyboards, virtual keyboards, and
  unselected external keyboards remain unchanged.
- The installer backs up the existing Karabiner configuration, validates the
  live profile, and automatically restores the backup if activation fails.
- The package contains no telemetry, account requirement, personal app
  settings, pre-enrolled keyboard identifiers, or live Karabiner configuration.

## Requirements

- macOS 15 or newer
- Karabiner-Elements 16 or newer
- A connected physical Windows keyboard
- Default macOS Modifier Keys and no active `hidutil UserKeyMapping`

Karabiner-Elements requires macOS Input Monitoring, Accessibility, background
service, and DriverKit approvals. Finder `Alt+F4` may request Automation
permission the first time it closes a Finder window.

## Known limitations

- The preview `.command` bundle is not Apple-signed or notarized.
- Karabiner-Elements must be installed separately and its Apple permissions
  must be approved manually.
- Keyboard firmware or Fn-lock must expose F1–F12 key events; model-specific
  consumer-key usages are not guessed globally.
- Physical shortcut smoke testing is recommended on every newly enrolled
  keyboard.
